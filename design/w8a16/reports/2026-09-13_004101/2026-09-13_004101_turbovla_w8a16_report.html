1. 先看结论

数学和 RTL 快速检查通过。 INT64 黄金模型、INT40 边界、INT16 饱和以及 Verilator 的 PE、4×4、16×48、requant 和 GEMM 测试都通过。Icarus 的两个短 smoke 也通过。

这条硬件路线是一颗 DSP 做一个有符号 INT16 激活乘一个有符号 INT8 权重，阵列共有 768 颗 DSP。3.298 ns 只用于周期模型，换算出的理论峰值约 232.9 GMAC/s；这不是已经完成布局布线后的频率结果。

当前仍有两个关键缺口。服务器和本地都没有 Vivado，因而没有 LUT、FF、DSP、BRAM、WNS 或 Fmax 实测；也没有在本轮重跑完整 LIBERO 成功率。UNISIM/DSP48E2 smoke 同样因 xvlog 不存在而未做。

2. W8A16 数据流和端口

量化定义为 q_a=clip(round(x/s_a),-32768,32767)、q_w=clip(round(w/s_w),-128,127)，累加器计算 sum(q_a*q_w)。A16 指的是进入 GEMM 的激活张量是 16 位，不是 GELU 或其他激活函数的位宽。

CTX 激活口和写回口都是 256 bit，也就是一拍可传 16 个 INT16；WRAM 的逻辑权重输入是 384 bit，对应 48 个 INT8 权重。每个 PE 保存 40 bit 累加值和快照，快照读出后再重量化成 INT16。下一层若继续使用该结果，也必须保持 INT16，不能写成 INT8 后再称作 W8A16。

3. 算子清单和编译器覆盖

当前清单来自冻结 checkpoint 的参数形状，共 672 条记录，其中 233 条二维矩阵被标为 W8A16 candidate，其余 439 条是 embedding、偏置、归一化参数或其他需要重算／fallback 的项。这个数字是参数形状统计，不是完整运行时调用次数；动态 BMM、卷积展开和每层真实 token 数还需要运行时 trace 才能补齐。

编译器输出 8 条代表性描述符：线性层和一个 QK 矩阵乘走 gemm_w8a16；Softmax、LayerNorm、GELU 记录为 fallback cost event。完整参数清单和代表性描述符分别保存在机器可读 JSON 中，避免把代表样例误称为完整指令流。

8. 尚未做和下一步

未做：真实整数 GPU kernel、Vivado OOC／post-route、功耗、完整 LIBERO 成功率和端到端系统集成。下一步如果要把这条路线变成硬件性能结论，优先补齐两件事：一是运行时 trace，列出真实 Linear、Conv、MHA、BMM 的调用和 fallback 时间；二是在有 Vivado 的环境完成 1×1、4×4、16×48 的资源和时序报告。只有这两项完成后，才能判断 768-DSP 阵列是否值得继续做物理实现。
